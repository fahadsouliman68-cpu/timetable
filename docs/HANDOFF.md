# ملف التسليم للمحادثة الجديدة

## المشروع
تطبيق أندرويد offline لإدارة جداول حصص مدرسة ابتدائية، بالعربية وRTL، وأرقام لاتينية، وأشهر سورية، ويعمل على الهاتف فقط، مع نسخ احتياطي محلي بدون سحابة.

## المستودع والبناء
- المستودع: `fahadsouliman68-cpu/timetable` (خاص). الفرع: `main`.
- البناء على GitHub Actions فقط، لا يوجد Android Studio.
- `domain-tests` يشغّل اختبارات المنطق (36 اختباراً) عبر `scripts/test-domain.sh`.
- `android-build` يبني `debug-apk` ويرفعه كـ Artifact.
- المستخدم يعمل من الهاتف، وينزل APK من تبويب Actions ثم Artifacts.

## الحالة الحالية (آخر commit: a6d91ab)
- المنطق الداخلي (domain): محرك الجدولة CSP، والتحقق، وتقييم الجودة، والفحص الأولي، والتقويم السوري. كله مختبر.
- Room: 15 جدولاً، الإصدار 1.
- شاشة الإعداد: اسم المدرسة، العام الدراسي، المدير، أيام الدوام، وردية صباحية واحدة (بداية، عدد الحصص، طول الحصة، الفاصل). تُحفظ عبر `SetupRepository` بعد التحقق بـ`SetupBuilder`.
- عند الإطلاق: إن وُجدت مدرسة محفوظة تظهر شاشة الترحيب، وإلا شاشة الإعداد.
- نتائج: `domain-tests` أخضر، و`android-build` #4 أخضر.
- لم يُختبر بعد على الهاتف: بقاء البيانات بعد إغلاق التطبيق وإعادة فتحه (معيار القبول الأول للمرحلة 1).

## المطلوب لاحقاً (بالترتيب)
1. التأكد من بقاء الإعداد بعد إعادة التشغيل على الهاتف.
2. الوردية المسائية في شاشة الإعداد.
3. إدخال الصفوف والشعب والمواد والمعلمين والخطط الأسبوعية.
4. ربط قاعدة البيانات بالمحرك (تحويل Entity إلى SchoolData).
5. عرض الجدول وتوليده وعرض التعارضات والجودة.
6. التقارير وPDF والنسخ الاحتياطي والاستعادة.
7. اختبارات الهجرة (migration) للـRoom.

## قرارات معلّقة
- عتبات القبول في `docs/03-ux-tests-plan.md` القسم 12 تحتاج موافقة بعد القياس الفعلي.
- سياسة الاستبدال للمعلم الاختصاصي عند امتلاء خانات الفصل: تحتاج قراراً.
- التوقيع للإصدار (Release signing) يتم عبر GitHub Secrets، ولا تُرسل كلمات المرور في المحادثة.
